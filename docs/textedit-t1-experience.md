# TextEdit T1 体验：读对当前表达，给出自然建议

版本：0.3.0（build 4）。本阶段只读：可以检查语境、候选和修改对照，原文不被写回。

## 开始使用

1. 从旧应用 LM 菜单退出 LingoMend，避免两个版本争抢快捷键。
2. 打开项目 `.build/LingoMend.app`。当前完整流程在 TextEdit，旧“打开输入体验”入口已收起。
3. LM → 设置，勾选 TextEdit。使用已有 DeepSeek 地址、模型与钥匙串密钥；打开模型服务并保存即可请求真实建议，每次可能计费。
4. 需要辅助功能权限时，在系统设置的隐私与安全权限页允许这一个 LingoMend.app。重新构建的临时签名可能需要移除旧条目、重新添加同路径应用。
5. 新建 TextEdit 合成测试文档。按 ⌃⌥L 求助，⌃⌥. 收起；普通输入继续由 TextEdit 和原输入法处理。

网络关闭时只有文中的固定样例有演示结果；其他句子会提示本地演示未覆盖。真实服务失败时不会退回固定演示。

## 先体验这八项

每条单独一行。除第 3 项外不选中文字，把光标放在目标句中或句末。不要使用真实私密材料。

| 用例 | 输入与操作 | 检查重点 |
| --- | --- | --- |
| 1 | `This works 轻载条件下.` | 出现工况表达；已有英文保留 |
| 2 | `I very like 这个方案.` | 同时修正英文，例如 `I really like this approach.`；标签提示包含英文修正 |
| 3 | `I am 负责 this project.`，只选“负责” | 读取语境是完整句子，建议补出 `responsible for`；显示“只改选区” |
| 4 | `We need 降低损耗 without 增加成本.` | 一次处理本句两处缺口，保留原意 |
| 5 | `She go to the lab yesterday.` | 最小纠错，例如 `She went to the lab yesterday.` |
| 6 | `I made a decision yesterday.` | 返回“这句可以”，不强行换词 |
| 7 | `这个方法可能会降低损耗。` | 输出自然英文，保留“可能”的不确定语气 |
| 8 | `First stays. This works 轻载条件下.`，光标第二句 | 读取语境只有第二句；模型不收到第一句 |

模型输出可以有合理变体；判断是否准确、自然、保留自己的表达，不要求逐字匹配。

## 再检查主体性和边界

- `If the load is reduced, we can`：用户还在构思，不应替作者补出新的结论。
- `The label reads “轻载条件下”.`：引文保持原样，不把所有中文当缺口。
- `Dr. Li checks Fig. 2 at 0.5 A 轻载条件下.`：句子范围不被缩写或小数截断；技术信息不变。
- 发请求后继续输入、移动选区或切文档：旧候选关闭/丢弃，不自动重新生成。
- 正常写作而不求助：不出现候选，不发自动模型请求。
- 选中多句或超过句子上限：LM 菜单给出范围提示，不把整篇发出去。

界面使用本地句子边界规则，缩写在句末、复杂引文等含糊边界需要试用反馈。语义、专名识别和自然程度也需要用户判断。

## 反馈格式

请告诉我：输入的合成句子、光标/选区在哪里、读取语境是否正确、候选是否自然、是否改了观点或语气、是否打断思路。

本轮自动检查：范围、请求结构、模拟服务、取消与缓存测试；构建和签名检查。真实 TextEdit 展示、模型质量和输入法体验由你试用验收。详细运行记录留在本地被忽略的目录。
