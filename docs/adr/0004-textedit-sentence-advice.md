# ADR 0004：TextEdit 句子级表达帮助

日期：2026-10-09。状态：采用。

## 决策

1. 当前阶段主入口仅支持 TextEdit，按快捷键请求帮助。后台保持安静，变化通知仅用于取消正在进行的操作或使候选失效。
2. 使用当前句子作为语义上下文；显式选区是可修改边界。无选区时允许为自然表达修正本句已有英文，保留可用措辞。
3. 句子请求的 `target`、`left`、`right` 合计最多 600 UTF-16 单位。界面显示读取语境；模型仅返回 `target` 的建议。
4. 模型保留作者观点、语气、技术信息；补缺与必要纠错一起完成。返回 `suggest`、`unchanged`、`clarify` 或 `unsupported`，解释单独按需请求。
5. T1 只读交付：展示候选和编辑对照。T2 再接安全写回和原生撤销；T3 接按需解释与最近建议回看。

## 理由

旧流程的中文片段替换无法处理 `I very like 这个方案.` 的英文结构问题，也丢失了显式选区外的搭配语境。
句子级帮助让用户获得准确、自然的英文，并从差异看到需要学习的表达；按需触发保留构思过程。

## 实现与验证

- `SentenceScopeResolver` 在本地解析句子边界，并保留不可编辑上下文。覆盖常见缩写、小数、引文、括号、换行、emoji 和组合字符。
- `SentenceRequest` 在发请求前检查长度与非 prose 内容；`SentenceAdvice` 检查返回结构、数字、部分单位/缩写/语气标记、引文和上下文重复。
- 模型不返回编辑坐标、应用身份或工具调用。本地构建建议与差异。
- 外发只有目标句和意图提示。读取桥接可能在本地先取得整个聚焦控件；不保存完整写作或运行日志到 Git。
- 提示词保留作者主体性，并限制自动续写、词汇升级和固定风格。机械校验不能判断所有语义变化，候选质量由 TextEdit 合成试用验收。

DeepSeek JSON object 参数依据 [官方 JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode) 与 [Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion)，通过 find-docs / Context7 核对。JSON 输出仍需本地验证。

## 后续影响

ADR 0003 的片段流程保留为已有模块与回归基线；不再指导当前应用主入口。现有密钥和端点配置继续复用。
旧伴随模式、跨应用接受和风格设置在 T1 主入口不生效；界面说明当前能力。技术兼容工作先围绕 TextEdit 收敛。
