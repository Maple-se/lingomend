# ADR 0008：全局写作和明确选中的短段落

状态：T3 核心实现；第三方应用真实控件体验待用户反馈。

## 范围与能力

⌃⌥L 在允许的前台应用发起；使用当前聚焦控件的 AXValue 与 AXSelectedTextRange。
应用名不决定能否写作；`EditorCapabilities` 检查文本角色/明确可编辑性、enabled、
可写文本属性和范围设置能力。只读或无法确认可编辑性的控件拒绝写回，并提示用 ⌃⌥D 阅读。
新全局开关默认关闭；原 TextEdit 许可仍有效。每次操作只允许当前前台应用，
通知观察仅在本次请求和候选期间启用；不轮询、自动生成或读取后台应用。

无选区仍是当前完整句（上限 600 UTF-16），含光标左右。单句内选区借用所在句语境，
只许可修改选区。明确选中的多句、跨行或较长片段上限 1200，通过 `WritingScopeResolver`
成为 `selected_passage`；模型只取得该选区，不借此扩展整篇。未选中时不自动升级范围。
段落响应上限 1800、1400 output tokens / 15 秒，保持段落换行数量和原有语义约束。
句子原预算与既有数字、技术词、否定、不确定性和引用检查继续有效。

## 原生写回

通用 `MacOSNativePasteDriver` 复用 T2 的 `NativeTextPaste` 事务：明确接受、再次捕获、
身份/源文/版本/选区核对、局部范围、单次按 PID 定向的 ⌘V、有限结果核对和剪贴板恢复。
只产生 V 的 Command 按下/释放；不产生 Return，不执行任何聊天发送动作。
普通 Return、Tab 和原输入法不被占用。编辑器自身决定撤销分组；只验证成功的粘贴才报告接受。

可设置范围时，继续计算目标内最小连续差异。不能设置范围但用户已有明确选区时，
计划保留完整原选区，且驱动只在当前选区仍完全一致时使用；不通过按键移动/扩大选区。
不能设置范围且没有选区时拒绝，用户可先选词句再试。

AX 提供基础富文本时沿用本地 run 保持；已暴露的复杂/未知样式拒绝，不悄悄剥离。
TextEdit 继续要求可靠基础富文本。其他只暴露普通文本的输入控件使用纯文本剪贴板载荷，
让原编辑器继承其输入样式；不保证跨越富文本 run 的复杂样式。候选和设置说明这一边界。
剪贴板仅在接受期间借用，保留旧内容，外部新复制不覆盖；原剪贴板不传给模型。

## 验证与限制

自动检查包括跨应用身份更换拒绝、短段落范围、无选区不升级、只读/禁用控件拒绝、
无范围 setter 的明确选区、结构/长度/语义锚点检查，以及隔离 NSTextView 的纯文本单次
粘贴、光标、一次原生撤销和剪贴板恢复。使用独立测试剪贴板，不操作真实聊天。

这证明通用流程及原生编辑语义，不证明微信、备忘录、Safari、VS Code、Codex 每个
具体控件都已实测。它们同属目标范围。AXValue/选区/定位未暴露的自绘控件仍需基于
实际反馈适配；不会把缺失能力标为成功，也不借用隐藏复制或整框覆盖来伪装兼容。
体验见 [T3 全局体验](../t3-global-experience.md)。
