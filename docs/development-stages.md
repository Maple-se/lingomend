保留作者观点、语气、技术事实和可用措辞；学习由用户主动展开。

### T3 范围与交付顺序

用户已明确产品是全局伴随助手，不以 TextEdit 或某个应用白名单定义功能。
保留现有输入法，后台不主动生成；写作候选贴近光标，解释仅在主动阅读/学习时展开。

1. 选区阅读：新增 ⌃⌥D。英文词/短语给出当前语境中的中文含义、所在句的解释及简短用法；
   选句给出自然中文含义。不修改原文。仅有选区时明确提示缺少语境，不编造所在句。
2. 全局文本接入：按选区、语境、可编辑性、定位与原生写回能力分层。
   覆盖普通输入框、富文本、网页只读选区和文字 PDF；读取只在快捷键触发时发生。
   不使用隐藏 Copy 来获取选区，不监控剪贴板，不加 OCR 或浏览器扩展。
3. 写作：⌃⌥L 无选区处理完整当前句，有选区支持词句及短段落。
   自然化必要英文搭配，不限定“只改中文”，但保留作者事实、观点、语气和技术信息。
   仅明确接受才原生粘贴；写前重验来源、焦点、内容与选区，不自动发送聊天消息。
4. 集成与体验：TextEdit 回归；Safari 输入与网页、备忘录、微信、VS Code、Codex、
预览/浏览器文字 PDF 都是目标，不以安装新应用或十应用全量测试阻塞交付。build 11 增加前台应用
   诊断标识、AXStringForRange 读取兜底、前台窗口有限编辑控件搜索，并允许 TextEdit 在无法读取格式时经安全校验降级为普通文本写入。
   build 13 为 Electron/WebKit 前台窗口启用增强辅助功能树，并搜索 AXContents/AXVisibleChildren 等结构路径，
   同时按可写属性识别自定义编辑控件。
   build 14 为缺少 AXBoundsForRange 的控件使用已验证编辑控件边界定位候选，并尝试窗口/应用根节点的文本接口。
   build 16 补充无正文采集摘要；空 AXValue 的范围/富文本接口兜底、标记选区与索引适配、
   微信/自定义控件的手动辅助功能树请求、焦点读取失败后的窗口后备路径；移除无焦点依据的角色评分选取。
   Safari 观察器区分文本与焦点通知，源变化/选区变化/焦点变化/重读失败分开记录。
   这些是实现层修复，Word、VS Code、微信的实际通过情况以新构建试用为准；
   [build 16 体验步骤](t3-capture-build15-experience.md)同时包含 Codex 与 Safari 回归。
   控件不暴露能力时给出具体限制；不能以“有输入框”为由虚称已经兼容。

首批自动检查覆盖范围/上下文来源、重复词消歧、PDF 换行、模型结构和无语境降级，
再覆盖全局编辑的安全边界、取消/乱序、原生撤销和剪贴板恢复。
保留现有联网开关和模型配置，单次请求有界、可取消，不自动重试。
阅读/写作过程只记录固定事件与有限指标，不记录文本、应用内容或网络正文。
阶段完成后提供构建版本、提交、已验证边界和简短用户测试步骤，等待反馈。

T1 主入口只处理 TextEdit，由 ⌃⌥L 发起；无自动生成、写回或解释请求。
模型请求只包含一个完整句子的 target/left/right 与本地意图提示，合计最多 600 UTF-16 单位。
选区为编辑边界，所在句为只读上下文。句子建议 JSON 返回 suggest/unchanged/clarify/unsupported；
本地检查结构、长度、数字、部分单位/术语/语气标记和不可编辑语境重复。
640 output tokens / 15 秒；保留 3 秒启动节流、30 秒限流/凭据冷却、最多 8 条短期内存缓存。
T2 明确接受时借用剪贴板完成局部富文本原生粘贴；用户已批准此方式。
整篇不覆盖，原生编辑器负责撤销；保存原剪贴板并在本次标记/版本仍一致时恢复，检测到新复制则保留。
未知格式/不可可靠保存的剪贴板内容拒绝写回；发送后结果不明不重试、不自动撤销。
以上是 T1/T2 基线行为。T3 依据上方新范围接入阅读与多应用；收藏仍留给后续阶段。

体验步骤：[TextEdit T2](textedit-t2-experience.md)，设计：[ADR 0005](adr/0005-textedit-native-acceptance.md)。
自动验证包含隔离原生 NSTextView 的一次粘贴/撤销与基础格式；不等于真实 TextEdit 已验收。
每阶段保持下述提交与停点规则。

T2.1 只补诊断，不改变求助策略、写回授权或模型配置，不提前启动 T3。
开发版日志默认开，正式版及缺失/错误渠道默认关，独立保存各渠道偏好。
只保存固定事件和有限指标；真实文本、候选、剪贴板、网络正文、密钥及自由错误描述不写入日志。
实际日志位于用户 Library/Logs 下；源码、自动测试与使用文档可推送，日志不可推送。
体验步骤：[本地诊断](diagnostics-experience.md)，设计：[ADR 0006](adr/0006-local-diagnostics.md)。

## 历史交付记录（2026-10-03 起）

以下记录旧片段流程和已有基础模块；当前产品行为及验收以 T1–T4 计划为准。

产品方向确认：2026-10-03。保留用户现有输入法，LingoMend 是伴随式表达助手，
不是 TypeTide 式“快捷键 → 大预览 → 替换”的产品，也不是新的中文输入法。

> The goal is to need us less.

## 协作与版本管理

每阶段执行：定义范围 → 实现 → 自动测试和构建 → 本地 Git 提交 → 停下来汇报。
汇报包含完成范围、未验证边界、下一阶段计划和用户体验测试步骤。
收到反馈后再调整和开始下一阶段。不默认启动 computer use 测试。
用户已授权每阶段同时本地提交和远程推送。遵循 Conventional Commits，按可独立验证的
功能边界拆分提交，核对暂存差异与远端分支，普通快进推送，不强推。合成测试材料、验证日志和敏感信息
保留在被忽略的本地目录，不进入提交。公开的测试步骤不得包含个人操作记录。

## 阶段 1：伴随式候选与本地体验骨架（已交付）

- 菜单栏常驻；保留现有输入法，不注册输入源，不拦截普通输入键。
- 增加无需系统权限的本地输入体验页：边写英文边留中文占位，停顿后出现简短候选；
  接受后继续输入。学习解释仅主动展开。
- 跨应用只在明确启用且勾选的应用里订阅辅助功能通知，无全局按键记录、无轮询。
- 当前段落、邻近光标的中文占位才可触发候选；内容/焦点/选区变化后取消旧结果。
- 非激活候选面板靠近光标，不抢编辑器焦点。定位失败不退化为居中大弹窗。
- 先用本地固定样例，当前阶段不联网。已开始的模型与学习底层工作仅作为后续基础，
  不把尚未体验验证的能力标为正式功能。
- 跨应用接受保持实验性、默认关闭，限定 TextEdit/Safari；选区、文本、元素身份
  写前重验。用户反馈的替换异常与原生撤销仍未验证，不宣称通过。
- 候选出现时才注册接受/学习/收起组合键；不接管 Tab、Return 或中文组词操作。

完成门槛：Swift 自动测试通过、本地 app 可构建、提供体验步骤与本地提交。
用户重点判断“是否打断思路”，不要求十应用覆盖。

## 阶段 2：真实建议与安全接受

本轮交付其中的 **API 接入切片**：DeepSeek 预设、钥匙串密钥、显式联网、合成连接测试、
独立的短候选/按需解释链路、有限上下文、取消/超时/格式校验与节流。先由用户在
无需辅助功能的原生编辑器里测试真实服务，再决定是否启用跨应用联网。
不会自动读取用户密钥或替用户运行付费验证；公开测试步骤不记录个人操作结果。
跨应用接受异常、输入法组合态和原生撤销兼容性仍未确认，不宣称整个阶段 2 已完成。

- 启用 OpenAI-compatible/本地模型配置、钥匙串凭据和明确的联网范围。
- 按语境提供最小修改；约束响应、超时、取消、乱序结果与错误处理。
- 中文组词/未提交文本的应用差异与通知覆盖作为输入适配重点。
- 根据阶段 1 的体验反馈修复跨应用接受异常；验证 TextEdit/Safari 原生撤销。
- 完善接受后的光标连续性与拒绝状态；只有安全边界通过才移除实验标记。

API 实现约束与默认值：

- `https://api.deepseek.com` + 可编辑 `deepseek-flash`，直接 `POST /chat/completions`；
  使用 Swift URLSession，不引入额外 SDK、后端代理、Agent 或向量库。
- 候选只返回 `status` / `replacement`，允许 `abstain`；本地代码重建段落，不让模型决定范围。
- 中文占位最多 40 个 UTF-16 单位，上下文左右各最多 200；只在当前范围内截取。
- 主动学习另请求固定短语的解释/类别/少量等价表达；候选阶段不生成解释。
- 明确 `thinking.type = disabled`、`json_object`、非流式、低温度；
  候选 192 tokens / 12 秒，解释 512 tokens / 30 秒。
- 输入停顿约 1 秒；候选联网启动至少间隔 3 秒；限流/凭据拒绝冷却 30 秒。
  最多 8 条短期内存缓存，无落盘、无自动重试、无失败后偷偷退回演示模式。
- 写作、选区、焦点和设置变化取消/丢弃旧候选；学习关闭取消解释请求。
  客户端取消不保证服务端停止计费。
- 设置按端点存钥匙串凭据；网络开关默认关闭，连接测试按钮单独说明付费与合成文本。

参数核对使用 find-docs / Context7 和 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)、
[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)；模型名称与参数可随服务变化，
真实延迟/质量以用户测试为准。Chat Completions 的 JSON object 不是严格 JSON Schema。

## 阶段 3：按需学习与独立使用证据

- 主动展开解释和差异；主动保存表达、表达列表、删除和清空。
- 辅助接受与后来的自主使用分离；不因一次复制就判断掌握。
- 学习页展示证据与谨慎的进度描述；可选本地统计，避免奖励 AI 依赖。
- 不保存全文，不把学习卡片或日志传到遥测服务。

## 阶段 4：体验打磨与发布准备

- 在已有/用户愿意提供的应用上扩展兼容性；不自行安装客户端。
- 测量启动、空闲资源占用、候选延迟和长文本行为。
- 稳定签名与权限身份、打包、发布说明、许可证/依赖复核。
- 开源发布内容复查；验证日志始终不进 Git。

阶段可随反馈调整，但不能跨越阶段停点直接继续下一阶段。
