## 沉浸式体验要求

用户希望 LingoMend 像输入环境的一部分运行，而不是让用户在菜单栏和浮窗之间来回切换。后续设计遵循以下约束：

1. **请求结果靠近触发位置。** “正在识别当前表达”应显示在光标或选区附近；候选生成后，原卡片以轻量过渡转为建议卡片，保持位置和阅读上下文。
2. **菜单栏只承担状态与异常。** 正常候选、解释和接受不再通过菜单栏弹出卡片；菜单栏保留状态、设置、权限和错误/异常提示入口。
3. **不改变按需触发。** 后台不主动分析、不续写、不自动弹出建议；快捷键仍是用户表达求助的明确动作。动效只连接“请求中 → 结果”，不增加额外确认步骤。
4. **保持非激活与可访问性。** 卡片不能抢编辑焦点；键盘接受/取消继续有效；结果过长、位置不可用或窗口切换时退回现有安全提示。
5. **错误可见但不打断。** 只有读取失败、权限、网络、过期候选和写回异常才需要显著提示；普通解释失败仍保留接受入口。

## 句子识别与切分待优化

当前完整句范围在光标位于句中、缩写、混合中英文、换行和网页/富文本控件中仍可能不符合用户预期。下一轮应以合成案例和真实应用日志分别检查：

- 光标在句中时，边界是否停在当前句而不是只读到光标前半句；
- `Mr.`, `e.g.`, 小数、版本号、URL 拒绝规则和中文标点是否误切分；
- 中英文混合、连续中文占位和未完成句是否保留作者未完成的部分；
- 显式选区优先于自动句子范围，跨句选区仍必须由用户明确授权；
- TextEdit、备忘录、Codex、Safari、Word 暴露的正文/选区差异是否能在日志中区分，而不是统一归类为“句子错误”。

后续实现应先补范围解析的确定性测试，再做应用回归；不能用扩大读取范围掩盖切分错误。

## 后续排期建议

1. 先补 TextEdit 的 build 20 回归记录，完成 T4.1 的三应用验收门槛。
2. 建立“光标附近卡片”的 UI 原型和非激活定位协议，先在 TextEdit/备忘录/Codex 验证位置、焦点和键盘操作。
3. 增加句子边界回归集，覆盖缩写、数字、混合语言、换行和句中光标；将失败原因拆为范围解析、应用采集和模型澄清。
4. 再评估是否把候选卡的布局改为就地转换；在此之前不移除现有安全浮窗和错误提示路径。

这份记录只描述后续方向。T4.2 的本地表达卡片、周报、CEFR 和独立使用证据仍按阶段计划排在后面。
