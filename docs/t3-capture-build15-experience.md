# build 16：跨应用采集与诊断体验

本页记录 build 16 的采集用例；当前启动与菜单步骤见 [T3 全局体验](t3-global-experience.md)。
当时版本为 0.5.2 / build 16。自动测试覆盖范围读取策略、选区边界、控件消歧规则、
日志白名单及既有编辑事务，不代表真实 Word、VS Code、微信已通过。

从 LingoMend 菜单栏图标退出旧进程，再打开 `.build/LingoMend.app`，核对菜单中的 build 16。
若系统提示辅助功能权限，手动授权当前构建。模型设置与联网开关沿用本地配置。

## 三个待验证应用

1. VS Code 新建一个普通文本编辑页；Word 新建一个普通文档；微信使用可丢弃的合成草稿。
2. 写入 `I very like 这个方案.`，仅保留一个光标。先将光标放在 very 中间按 ⌃⌥L；
   再取消候选，选中整句按 ⌃⌥L。分别记录两种方式是否显示正确目标的候选。
3. 候选原文正确时才按 ⌃⌥↩ 接受，松开组合键，核对原文变化，再按一次 ⌘Z 检查恢复。
   微信草稿不发送。
4. 在同一合成正文选中一个英文词，按 ⌃⌥D，检查是否显示当前句的语境解释。
5. 失败时提供应用名、光标/选区方式和提示文字即可；后续分析本地 captureChecked，
   不需要提交真实文档或聊天内容。

## Codex 与 Safari 回归

- 在输入区重复光标中间、显式选区、接受与一次撤销。
- Safari 阅读在同一合成句中选词后按 ⌃⌥D，候选/解释出现后保持不输入、不切窗口，
  留意是否仍自行收起；再主动移动光标/改变选区，确认旧候选失效。
- 同一窗口有多个输入框时，从第一个框发起求助后切到第二个框，旧建议应停止接受，
  第二个框不得被旧建议改写。

## 实现边界

采集使用 AX 的文字/选区接口，包括具备真实索引映射的标记范围。系统焦点链失败后
继续检查同一前台窗口的焦点节点或焦点容器中唯一可确认的可编辑后代。
没有明确输入目标或存在多个候选时拒绝写作，不靠角色评分猜输入框。

请求增强/手动辅助功能树时保留结果码；写作首次读取不可用会在 100 ms 后做一次本地重读，
不触发模型重试，接受前的同步检查不等待/重试。剪贴板仍只在明确接受时借用。

日志与个人试用审查保留本地，不进入 Git。阶段停点是交付可试用构建和诊断能力，
下一步依据用户实测结果决定是否需要应用专用适配。
