# 合成表达质量验收

本页定义可复用的验收方法，不保存运行日志或私人模型响应。有效需求见 [产品需求](product-requirements.md)；当前交付范围见 [状态页](status.md)。

## 本轮案例

[20 条固定合成案例](../Tests/LingoMendAppTests/Fixtures/sentence-quality.json)覆盖：单/多中文缺口、必要英文纠错、正确英文不改写、否定/不确定性、数值单位术语、中文专名与引文、未完成观点、选区语境与扩大范围澄清、文本内指令和非 prose。
它们是首批代表性语义抽查，不是完整语言基准，也不等同早期方案中的 100 条长期样本目标；后续按真实反馈补案例。

每条分别判断：范围是否正确、事实/立场/语气是否保持、英文是否自然且改动必要、有无续写或增加观点。不能因为 JSON、状态或字符串检查通过，就把语义标为通过。

## 自动检查与真实请求

普通 `swift test --disable-sandbox` 只验证案例输入和确定性实现，真实服务测试默认跳过，不读凭据。
要使用已开启的模型配置做显式合成评测：

```sh
LINGOMEND_LIVE_QUALITY=1 swift test --disable-sandbox --filter LiveSentenceQualityTests/testLiveSyntheticReview
```

这会从应用设置和 Keychain 读取已有配置，通过应用实际 SentenceService 顺序发送最多 20 条合成请求，遵守现有节流与校验。不开启被关闭的模型开关，不读取当前应用正文，不自动循环重试失败请求。
可能产生费用；生成结果写入本地 `Diagnostics/sentence-quality-review.json`，继续被 Git 忽略。不要提交报告、密钥或真实用户案例。

## 人工复核与停点

逐条阅读合成输入与实际输出，记录“通过／需修复／服务或本地校验拒绝／待复核”，写明依据。未执行的案例不能记为通过；语义有误时修正提示或本地约束，再重测相关案例。
合成评测的结果与实际应用的范围、粘贴、撤销验收分别判断。最终反馈要同时说明样本范围、异常和仍需用户判断的体验问题。

本轮抽查发现并修正了中文引文翻译、片段返回整句及明确短词无故澄清三类提示问题，并对受影响案例做了定向复测。安全拒绝文本内指令、原样保留未改写的非 prose 分别按其安全边界评审，不把它们当成代码支持能力。详细结果只留本地。
