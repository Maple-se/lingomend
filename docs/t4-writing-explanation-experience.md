# T4.1：写作解释与最近建议回看

当前体验包为 [交付状态](status.md) 所列的版本。T4.1 只增加一个主动学习分支：先看候选，用户点击“为什么这样改？”才请求简短解释；解释失败、超时或主动放弃都不影响候选的接受。接受成功后，菜单中的“最近一次建议…”只读回看本次会话最后一条已接受建议。

## 这次切片的边界

- 解释请求只发送当前候选的有限范围、原文和已显示的固定替换，不发送整篇文档、窗口标题或剪贴板。
- 解释响应只允许短中文原因、分类和最多三个英文等价变体；响应不能改变候选、编辑范围或接受决策。
- 最近建议只在内存中保留一条 `原文 → 接受后文本` 和可选解释；退出应用即清除，不写入表达库，也不保存全文或应用身份。
- 不自动显示解释、不主动续写、不把接受或查看解释计为掌握证据。周报、CEFR、复习和表达卡片属于后续切片。

## 同一构建的回归步骤

在 TextEdit、备忘录普通正文和 Codex 的可丢弃合成输入区域分别执行一遍。不要在微信或复杂格式区域做本轮结论。

```text
I very like 这个方案.
SECOND_LINE_UNCHANGED
```

1. 退出旧版，打开 `.build/LingoMend.app`，核对菜单显示与状态页相同的版本。确认辅助功能权限和对应应用按需访问已开启。
2. 将光标放在第一句 `very` 中间，按 `⌃⌥L`。候选范围应只覆盖第一句，第二行保持未读、未改。
3. 点击“为什么这样改？”。本地演示应显示类似“like 通常不和 very 这样搭配”的短解释；模型模式可使用等义措辞，但不能生成新的整句候选。点击解释前候选的接受入口应一直存在。
4. 按 `⌃⌥↩` 或点击“接受”。第一句被替换，第二行仍为 `SECOND_LINE_UNCHANGED`。回到编辑器按一次 `⌘Z`，第一句恢复原文。
5. 再次求助并接受一次，打开 LM 菜单的“最近一次建议…”。只读面板应显示接受前/后文本和刚才的解释；不能出现全文、窗口标题或其他历史建议。
6. 再次求助后按 `Esc` 取消。文本不变，解释请求可以取消；取消不应出现最近建议的新记录。
7. 可选故障边界：关闭模型服务或制造解释请求失败。候选仍可接受；日志只出现固定的解释开始/完成/失败事件，不出现原文、建议、解释内容或提示词。

## 反馈格式

请提供版本、应用和区域，以及“范围、解释、接受、第二行保持、一次撤销、最近回看、取消”各自是否通过。失败只需给界面提示和日志中的固定事件/operation；不要发送原文、完整日志或 API 凭据。微信采集仍按状态页延期，不纳入 T4.1 验收。
